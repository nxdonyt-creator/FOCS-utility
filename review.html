Highest priorities

Consistent preview and recovery

Two direct preview routes were guarded in 3.4. Boot conflict checks, destructive-policy compensation and journal durability need further work.

Account and release identity

Keep user actions under the initiating account. Move elevated code into protected storage and build a signed, verifiable release pipeline.

Applicability before a green check

A saved registry value is not proof that Windows or a browser used it. The catalog needs build, edition, app-version and effective-state evidence.

Measure one reversible change

The proposed repeated A/B/A workflow records the environment, verifies restoration and reports uncertainty. It is a design specification, not a shipped benchmark automation.

What changed in 3.4.0

The main Potato page now edits Fortnite’s existing NVIDIA driver profile through NVAPI, with texture LOD +1.5 or +3.0, filtering controls, Inspect, reviewed Apply and a separate Reset. The old INI editor is labelled In-game low graphics in an optional section.

Current Fortnite DX12 may ignore these overrides. Profile readback proves saved values; visible effects and performance gains remain unverified. The release also guards two preview routes and updates metadata and guidance.

NVIDIA research and exact settings · Checks performed · Known issues

The application remains unsigned. No new runtime regression, gameplay, GPU-profile application or latency measurements were performed. The broader audit roadmap remains proposed.
